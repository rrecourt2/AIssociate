# AIssociate pilot design

AIssociate keeps one reusable deal record of facts, assumptions, verification gaps and dependencies. The Investment Officer's brief sets purpose and depth. Documents are outputs; later system population will need agreed field mappings and validation, not a second fact store.

## Record and ownership

`register.json` is the master. One task commits changes; specialists return located findings for integration. Existing analysis entries hold the purpose and current direction (`strategy`) and dated decisions with their reasons (`timeline`). Hypotheses remain distinct from Investment Officer decisions. Record what has been integrated and what is still unreviewed or outside the record.

Sources retain original locations, versions and reviewed scope. Claims distinguish facts, assertions, assumptions, calculations and judgments. Existing ID links connect inputs, conclusions, gaps and document sections. Changed evidence reopens affected work; closure requires current support or an attributed Investment Officer exception. Original evidence remains authoritative.

`Analysis.md`, the workbook and client DDQ are generated views. Small investigations deliver the register and Analysis; other exports are optional. Keep one approved destination and verify retrieval in a fresh task. Local revision checks do not provide cloud locking.

## Tools and boundaries

The host provides the model, authorised connectors and publication. The plugin makes no network calls and stores no credentials. It does not enforce tenant permissions or retention. Internal records and revealing source links stay within their authorised audience.

`register.py` maintains evidence and views. Document Lead uses `fp.py` for supported Word builds and internal delivery bundles. The writer preserves Investment Officer edits and returns blocked changes as proposals; missing headings and predefined-table population remain unsupported. It cannot author tracked revisions/comments; these need a verified host tool or remain located proposals. Each run tracks one current document. Software readiness is not institutional approval or legal clearance.

See the [evidence workflow](../shared/workflow-contract.md), [Document Lead](../skills/fp-lead/SKILL.md) and [real pilot](../evaluations/pilot-acceptance.md). Existing `fp`/`officer` data keys and skill commands remain stable for compatibility. Measure Investment Officer effort, resumability and recorded cost; local tests do not establish writing quality or tenant integration.
